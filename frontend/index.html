About Council

What is Council?

Council is a local multi-agent chat orchestrator. You talk to Claude, Codex, Deepseek, and Hermes in a shared conversation. CLI agents run as subprocesses on your machine with filesystem access to your project; the Hermes slot routes through its configured OpenAI-compatible API endpoint. Mention an agent with @claude, @codex, @deepseek, or @hermes to dispatch them — plain names without @ are just references.

Agent roles

@claude — primary reasoning and planning. Good for architecture, debugging, and complex tasks.

@codex — fast implementation and refactoring. Excels at writing and editing code.

@deepseek — bounded analysis and support tasks. Handles research, verification, and small fixes.

@hermes — routes the turn through the configured Hermes/API bridge session.

Memory separation

Each agent has its own private effort memory stored under agent-memory/<agent>/. This memory is visible only to that agent across runs — it contains partial work, prior output, and continuity notes. The shared chat log (chat.md) is the single source of truth for decisions visible to everyone. Agents also receive session instructions from AGENTS.md or CLAUDE.md when present.

Compaction

When the chat grows long, click /compact (or it triggers automatically at a token threshold). A summarizer agent condenses earlier turns into a compact summary, keeping only recent turns in full. This saves tokens and keeps agents focused. The full archive is preserved in chat-archive/.

Sessions

Each session has its own chat log, agent memories, and config overrides. A session can target a project root, or be pathless for scratch work. Switch sessions from the left rail. They run independently — no data is mixed across sessions.

Dispatch queue

Send starts mentioned agents immediately, so separate requests can run at the same time. Queue sends the message but waits behind current work. Use the Queue dropdown in the top bar to see running and queued agents, and cancel individual dispatches.
